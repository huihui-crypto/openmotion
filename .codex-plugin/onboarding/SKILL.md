# OpenMotion onboarding

Follow the [shared installation contract](../../docs/install-onboarding.md#installation-success-reply). Open the library and deliver the maintained welcome followed by the prepared self-contained HTML cards. These are silent project renders, not original reference films. Accept automatic current-chat MCP activation independently; registration, a later connected chat and an independent probe do not prove it.

1. **Reuse the installation.** Source setup returns `inlinePresentation`, `preview`, `hostHandoff`, `detailsFile` and, for a known chat, `recovery`. npm setup wraps these in `onboarding`. Preserve the application, workspace, language and frozen random three-of-five IDs/order. If no setup result exists, run the installed `node --experimental-strip-types scripts/install-onboarding.mjs` once with the connection's workspace and the latest request's `OPENMOTION_ONBOARDING_LANGUAGE`. Never reinstall or enqueue a new user message.
2. **Use the current native connection.** Verify its workspace with `openmotion_get_project`. A working connection can deliver the component even when script host control is missing; do not block it on `hostHandoff` or report presentation as automatic-activation acceptance. If native discovery is missing/stale, use a supported existing-host reload. For `refresh_requested`, finish the current tool step, then run `recovery.command` with `recovery.args` once in this turn. Recovery preserves the selection, resource and workspace without another reload or library startup. Retain a missing-control blocker for separate activation acceptance. Do not start another app-server, change host security, restart Codex, or ask the user to restart a connection as a substitute for automatic activation.
3. **Open the library once.** Use the exact `preview.previewUrl` in this chat's right-hand browser, preserving query parameters and reusing the existing tab. Mark it as a deliverable when required by the browser tool. Opening is sufficient: no template inventory scan, screenshot audit or full-video playback check is needed for installation. Do not create a project.
4. **Deliver the prepared cards.** For `prepared`, publish the file using its SHA256 into the active chat's explicitly permitted visualization directory. Finish browser bookkeeping, then place `inlinePresentation.welcomeMarkdown` and the returned `contentReference` together in the final reply. Never withhold this route because native discovery is stale. For explicit `native_required` original-reference presentation, call the natively discovered `openmotion_show_template_recommendations` with the prepared IDs/order, request language and `onboarding:true`; do not repeat its welcome. If that welcome already appeared, use `onboarding:false`. Do not substitute builtins or resample. Record actual visibility separately from automatic activation; playback/content acceptance remains a separate user check.

If neither inline nor native cards can be displayed, open the library and use the top-level `welcomeMarkdown` fallback defined in the contract. Keep blockers in diagnostics and the receipt; preserve the incomplete presentation state and frozen selection for recovery.

The five-entry pool stays unchanged. Only the selected three prebuilt videos, posters and metadata enter the document. Original reference media stay in the separate native adapter. A readable prepared file does not prove visible delivery.

Use `zh`, `en`, `ja`, `ko`, `fr`, `es` or `pt` from the latest user request, otherwise `en`. Recreate prepares an unsent draft through a negotiated host extension, or copies the brief with a floating Toast. Only the user-sent brief authorizes creation/export. Continue an accepted recommendation through [accepted template selection](../../docs/install-onboarding.md#accepted-template-selection).
